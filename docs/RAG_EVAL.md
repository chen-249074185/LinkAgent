# RAG 评测

> 数据：`agent/rag_data/houses`（34 城、409 条有效房源）
> 模型：DashScope `text-embedding-v3`（1024 维，真实调用）
> 检索：`topK=5`，向量阈值 `1.5`，RRF `k=60`，向量/关键词等权

## 评测集

| 类型 | 数量 | 构造方式 | 相关性判定 |
|---|---:|---|---|
| 约束查询 | 102 | 每城 3 条：城市 + 区 + 25/50/75 分位预算 | 同城且租金 ≤ 预算 |
| 精确查询 | 96 | 每 4 条房源抽 1 条：城市 + 房源特征词 + 预算 | 同城且正文含特征词 |

## 结果（本次运行）

### 约束查询（城市 + 预算）

| 指标 | 纯向量 | 混合检索 | 变化 |
|---|---:|---:|---:|
| City Recall@1 | 100.0% | 100.0% | 0 |
| City Recall@3 | 100.0% | 100.0% | 0 |
| City Recall@5 | 100.0% | 100.0% | 0 |
| Budget Hit@5 | 92.2% | 92.2% | 0 |
| Precision@5 | 57.3% | 57.3% | 0 |
| MRR | 0.786 | **0.793** | +0.7pp |
| 平均耗时 | 2.20 ms | 2.97 ms | +0.77 ms |

### 精确查询（城市 + 房源特征词）

| 指标 | 纯向量 | 混合检索 | 变化 |
|---|---:|---:|---:|
| Exact Hit@1 | 97.9% | 97.9% | 0 |
| Exact Hit@3 | 99.0% | 99.0% | 0 |
| Exact Hit@5 | 99.0% | 99.0% | 0 |
| Precision@5 | 60.2% | 60.2% | 0 |
| MRR | 0.983 | **0.984** | +0.1pp |
| 平均耗时 | 2.15 ms | 2.45 ms | +0.30 ms |

## 结论

- 混合检索采用**重排**策略：只对向量候选加分，不额外引入关键词-only 候选。因此召回率与纯向量完全一致，MRR 提升 0.7pp（约束）/0.1pp（精确），不会出现“关键词把无关城市带进来”的回退。
- 在 409 条的小而干净语料上，向量召回已经接近饱和（City Recall@5 = 100%），所以混合检索的收益有限；它的价值主要在更大、更嘈杂、带编号/专有名词的语料。
- 我们也试过“关键词候选并集”策略：精确命中@5 能到 100%，但约束查询的 Budget Hit@5 会从 92.2% 掉到 91.2%。最终选择重排策略，优先保证不退化。
- 预算约束（Precision@5 57.3%）不是检索层能解决的：检索只负责召回，价格过滤需要上层技能或结构化过滤。这是后续优化点。

## 复现

```bash
# 需要 DashScope Key（从 .env 读取或直接设环境变量）
RAG_EVAL=true DASHSCOPE_API_KEY=xxx \
  mvn -pl rag-mcp -Dtest=RagEvaluationTest test
```

测试会打印 `RAG_EVAL ...` 行，包含本次评测的全部指标。
